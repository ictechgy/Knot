# Knot Native Preview — standalone Mac viewer

Experimental Apple Silicon macOS 26+ application. This package has no dependencies on Glimmer, Moonlight, Sunshine or the production Knot app. Swift 6 language mode is required. System Network/Security, VideoToolbox, AVFoundation, SwiftUI and AppKit implement transport, decoding and presentation.

From the repository root:

```sh
swift build -c release --package-path native-engine/macos --scratch-path build/native-engine/macos
swift test --package-path native-engine/macos --scratch-path build/native-engine/macos
```

`KnotNativePreview` is the executable product; `KnotNativeCore` contains strict invitation/JSON/framing, H.264 structure and input policy. The repository's separate preview packager creates the `.app`; these commands never launch its UI. No existing preferences, clipboard, keys, screens, histories or private caches are test inputs.

Paste a fresh secret invitation into the secure field using the normal user action, review its private IPv4 and exact certificate pin, then explicitly connect. The TLS verifier requires the pinned leaf DER, sole leaf trust anchor, current validity, server-auth purpose and DNS `knot-native`, without trust network fetch. After the one-use Hello, the app shows host approval pending, then encoder ready, then the first locally decoded/presented image. Nothing persists pairing/trust or reconnects automatically. The standalone preview is unsigned unless separately signed and is not a production release.

The native view uses aspect-fit image/input coordinates and a real fullscreen Space. A single unique window owns the preview's one session and presentation surface. Physical mode maps common ANSI keys, modifiers, navigation, function and numeric keypad keys to Windows set-1 codes. A user-selected viewer label (1–64 UTF-8 bytes, no controls) accompanies Hello as unverified approval context. It is not authenticated device identity. Physical key-up follows ownership of a forwarded down, including when modifiers are released first; normal repeat downs remain supported. Committed-text mode uses `NSTextInputClient` for local IME composition and sends committed Unicode only; composition is bounded, is never sent before commit, and has no remote preedit protocol. Candidate windows use the local pointer vicinity; v1 does not provide the remote caret. Control-arrow remains a Mac Space shortcut. Layout-specific keys, Korean/other IME behavior, remote shortcuts and pointer behavior need actual two-device acceptance. No global hooks, clipboard synchronization or audio are present.

The input queue caps 256 queued actions/16 KiB, coalesces only consecutive tail mouse moves without crossing action barriers; adjacent same-direction wheel packets merge only within the ±1200-axis cap and latches recovery after saturation or focus loss. A click explicitly restores input. Focus loss revokes unsent actions and sends ReleaseAll. Disconnect, close and presentation/decoder failure synchronously revoke the transport, cancel pending Hello/read/write continuations and prevent later submissions; host EOF cleanup releases accepted input. Disconnect never waits behind a blocked write to send a final packet. One reader and one writer share the full-duplex TLS channel, with bounded reads/writes and two-second heartbeats timestamped only after successful send. Before Ready, reads and silence have a 65-second budget and the combined approval/initialization stage has a 125-second overall budget. Windows bounds approval to60seconds; the viewer deadlines bound waiting for native startup. Native Open remains synchronous and a wedged OS/GPU call can outlive viewer cancellation; v1 adds no new handshake message. After Ready, ordinary ten-second peer silence handling resumes. Each pending operation owns a cancellable timer; completed fragment reads retain no deadline backlog. Ready has a 15-second first-decoded-image deadline, so heartbeats alone never establish streaming success. H.264 allocation/parameter-set/dimension limits and an asynchronous three-ticket admission gate bound both VideoToolbox work and output pixels retained for MainActor delivery. The sole reader waits for admission; compressed predictive units are not discarded. Stop/cancellation wakes admission, and documented successful dropped-frame completions release capacity without failing the stream. Late callbacks from invalidated decoder generations cannot display frames. Renderer failure is distinct from ordinary frame backpressure and terminates the connection even after streaming began.

H.264 scanning borrows a zero-based byte buffer and copies each accepted NAL into owned storage; sliced `Data` with a nonzero source index is supported. After streaming starts, two seconds of continuous presentation backpressure shows an authored display-lag message without failing or growing a frame queue. Successful presentation clears it; input recovery remains explicit.

Tests use malformed/duplicate/oversize protocol cases, fresh in-memory certificate trust checks, a real fresh loopback TLS peer and mismatched pin, an inert transport lifecycle and a fresh 64×64 synthetic software-H.264 encode/real decoder round trip. Blocked Hello/write fixtures verify prompt cancellation and suppression of late completion/queued input. An inert presenter verifies renderer failure after prior streaming, including asynchronous failure notification, and sustained backpressure/recovery. VideoToolbox callback isolation is explicit rather than inferred from an SDK annotation. Software encoding exists only inside the named synthetic test. Runtime never falls back to software host capture/encoding or to another engine. No app window, screen capture, real keyboard injection or user data is involved in these tests.

Cross-platform CI also sets `KNOT_NATIVE_WINDOWS_FIXTURES` to the fresh Windows media-test artifact directory containing `synthetic.h264` and `synthetic-codec.json`. The Mac test validates all 120 bounded Annex B access units and submits the complete 120-frame burst through the runtime decoder without per-frame output waits and verifies actual 320×180 decoded pixels, including periodic SPS/PPS+IDR. Missing or invalid files fail when the variable is set; without it the cross-platform test is explicitly skipped. The same fixture directory must contain fresh `native-test-public.cer` and Windows-computed `native-test-public.sha256`; the Mac verifies their exact DER hash, current OS validity, DNS/server purpose and negative pin/expiry cases through the runtime TLS evaluator. This synthetic MF→VT/trust result is separate from Windows hardware capture/encoding and two-device TLS acceptance.

Unverified device gates: real Windows 11 Home Desktop Duplication/hardware MF encoding, HDR/rotation failure behavior, LAN/Tailscale/Wi-Fi latency, macOS fullscreen rendering, keyboard layouts, IME, focus transitions and signed distribution. Host timestamps are recorded as host monotonic values, never claimed as one-way latency.

Wheel conversion uses separate authored preview scales (precise points versus line deltas); real device calibration and direction remain acceptance gates. Zero deltas are suppressed. Only an already-held button-up while the native view remains focused may clamp to the image edge; arbitrary letterbox clicks remain rejected, and focus loss still releases all input.
