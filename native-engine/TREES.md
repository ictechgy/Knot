# Native.10 file protocol v2: folders and Explorer handoff

This extends FILES.md. Both applications must update. Media Hello and Ready advertise filesVersion2; file Hello/Authorized use v2. The transport, exact certificate pin, source binding, per-operation TLS, active-run gate, deadlines and pacing remain unchanged. No peer supplies a Windows absolute path.

## File and tree grammar

Entry0x43 is strict `{entry,name,size,kind}` with kind `file` or `folder`. Folder listing size is0 (unscanned); file size is actual. Accepted0x47 is strict `{name,size,kind,count}`; files have count0, folders declare descendant-node count and sum of regular-file byte lengths. Put0x45 remains `{name,size}` for files. Get0x46 remains `{entry}` and selects the captured entry's kind. Complete0x4a remains `{name,size,sha256}`.

New TreePut0x4b is `{name,size,count}`. New Node0x4c is `{id,parent,name,kind,size}`: IDs are sequential1..count, root directory is implicit id0, parent must be0 or an earlier folder ID, and folder node size is0. Names obey the same strict safe-basename policy. No path string/array or additional shared JSON grammar is introduced. Require sibling names distinct under NFC/case-insensitive comparison and actual exclusive creation; depth<=16, count<=4096, aggregate raw node JSON<=1MiB, total file bytes<=8GiB. Folder source snapshots must be complete before Accepted; empty root folders have count0,size0.

After each file node send existing Chunk0x48 at file-relative offsets, then Finish0x49 with exact size and SHA-256, including empty files. Folder nodes have no chunk/finish. After all declared nodes send TreeEnd0x4d `{count,size,sha256}`. Tree SHA-256 covers, in order, U32BE(node JSON byte length), the exact transmitted node JSON bytes, then that file's exact content bytes (none for folders). This binds structure and contents without cross-language JSON reserialization assumptions. Receiver verifies all counts, lengths, per-file hashes and tree hash before one root publication. Complete reports the final collision-resolved root name, total data bytes and tree hash. Missing Complete after TreeEnd is unconfirmed and never automatically replayed.

Reserve data and node quota before receiving. Each ordinary file reserves1 node, each tree reserves count+1; maximum8192 nodes and8GiB per run, with no cancellation refund. Failed complete-snapshot admission creates no stage. One operation remains active, with at most32 queued top-level sends. Explicit Mac/Finder destinations must not exist; Windows may choose an exclusive collision suffix for the root. No directory merge or filesystem-copy fallback.

Keep source directories anchored by handles and open each component without following links, checking captured identity/type/size/mtime before and after streaming. Reject reparse/symbolic links, hardlinked files, special files and Mac application packages. Receiver creates a private root atomically, uses descriptor/handle-relative children, applies quarantine/MOTW to each leaf, flushes, checks live authority and exclusively renames the root once. Failure removes only the receiver-owned private tree; never recursively remove a replaced/unowned path. Hostile same-user or privileged local code and wedged OS operations retain FILES.md's explicit limitations.

Windows closes all staging descendants after flushing and verifying their current identities, while retaining the private pinned root without delete sharing. Its filesystem [does not permit a directory rename with open descendant files](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information). Failure cleanup reopens only known children relative to validated parent handles and deletes only matching owned identities; unknown or replaced children remain private. This does not add protection against hostile code already running as the receiver's own user.

## Actual Explorer drag

Input0x26 is a16-byte random nonce barrier, ordered after the user's left-down/moves. It arms only when that input session owns the left button; heartbeat remains0x25. File ExplorerCapture0x4e is strict `{nonce}` as32 lowercase hex. A matching barrier is single-use, expires after3seconds, and suppresses further non-release input until handoff finishes. Client cannot request capture while another file operation is active.

The host's dedicated STA OLE target is small, topmost, nonactivating and temporary. Only real DragEnter/Drop CF_HDROP+TYMED_HGLOBAL, with left-down and allowed COPY, can yield items. Do not use clipboard APIs, Shell selection, injected Explorer code, or arbitrary path requests. Extract data on Drop, release its STGMEDIUM on the STA, bound32 paths, and hand only copied path strings to the file worker. Release Windows' session-owned left button into the target after a supported DragEnter; failure or timeout revokes target and owned input. OLE callbacks never write TLS or wait on network.

Capture response uses Entry/ListEnd for1..32 selected roots with opaque IDs, separate from shared-folder listing. Capture pins only each selected root; no parent-folder browsing. IDs expire60seconds before use, are claimed once, and are revoked on disconnect/cancel. GET by such an ID uses the same file/tree stream. The receiving Mac retains promise delegates, serializes multiple fulfillment requests, fails late/released/disconnected drag callbacks, and starts no local drag until actual captured metadata arrives. Folder promises use public.folder. Rejected capture leaves media connected with authored guidance. An explicit capture cancellation0x4f `{nonce}` revokes only that handoff and its export IDs; no replays.

An external drag source can wedge an OS COM call. Expiry revokes payload publication and owned input immediately, while one bounded STA/target may remain until that OS call returns; further handoffs fail busy. This in-process preview does not promise a hard OS-call termination bound or isolate a hostile same-user process.

Fresh synthetic protocol/storage/OLE fixtures and actual Windows-generated vectors are required. Fixture rendering must not touch existing user UI/clipboard/files or invoke capture/input/network adapters. Synthetic checks do not claim live Explorer/Finder or hardware performance acceptance.
