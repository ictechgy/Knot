# Knot Native Engine v1 research contract

Status: experimental vertical slice; independent of Sunshine, Moonlight and Glimmer. Windows11 x64/Home logged-in SDR primary desktop host -> AppleSilicon macOS26+ viewer. Native.10 adds bounded file/folder transfer and active Explorer drag export; separate contracts are [FILES.md](FILES.md) and [TREES.md](TREES.md). No prelogin, lock/UAC secure desktop, microphone capture, ambient clipboard sync or virtual monitor. Native.11 adds explicit clipboard requests, opt-in trusted reconnect and signed-update infrastructure (publisher remains unconfigured). Native.13 adds separately authorized playback audio in [AUDIO.md](AUDIO.md). Native.18 adds negotiated live video profiles and video/input-only pause/resume; [VIDEO-CONTROL.md](VIDEO-CONTROL.md) is the authoritative extension contract. Earlier fixed-profile rules below remain applicable to peers without that negotiation. Existing product remains unchanged for comparison.

## Short-code provisioning

Native.5 adds the separate bounded PAKE enrollment service in [ENROLLMENT.md](ENROLLMENT.md). Windows Share explicitly authorizes one code holder; authenticated enrollment mints a distinct one-use T2 with a30second media-claim deadline. Only a valid T2 claim on a NEW existing pinned TLS connection uses this preauthorization. The provisioning socket never carries media. Legacy runs retain the120second invitation and explicit approval below; switching modes creates a fresh run and revokes the prior slot/grant. No saved pairing or automatic reconnect is implied.

## Transport and trust

One full-duplex media/input TLS/TCP connection, port48631 by default; TLS1.2 minimum, OS cryptographic libraries only. Authorized file operations use independent TLS connections on48634 with the same exact pinned certificate and a fresh active-run file capability; file bytes never use media/input queues. TCP is a deliberately simple proof transport, not a claim of Wi-Fi media optimization. Separate directions allow server video writes concurrently with client input writes. One sender and one reader per TLSstream. Strict bounded messages; stalled handshake/read/write ends that connection. File-only failures leave media active; media teardown revokes files.

Host creates a fresh self-signed server-auth certificate for each sharing run (subject/SAN DNS `knot-native`, SHA256 over exact DER). Its validity interval is creation time minus24hours through plus24hours, to tolerate clock skew and independently verify the fresh exported public certificate across CI jobs. This does not extend the120second invitation or persist trust: exact pin, OS validity/server purpose/name, one-use token and run-specific authorization remain mandatory: explicit approval in legacy mode, or a valid one-use T2 claim after Windows sharing preauthorization in enrollment mode. No existing certificates, services, accounts, settings or preferences are adopted. Any OS key-container resources created by this run have random names and owned cleanup. No permanent peer state in v1.

Host explicitly clicks Share, creates 32random invite-token bytes with CSPRNG, valid120seconds. Invitation is `knot-native:v1:` followed by unpadded base64url UTF8 JSON with EXACT keys `v`, `address`, `port`, `certificateSHA256`, `token`. v=1; address canonical private IPv4 RFC1918 or Tailscale100.64/10 only; port1..65535; certificateSHA256=64lowercasehex; token=43base64url chars decoding to32bytes. Invitation max2048UTF8bytes, no URL lookups or implicit connection. It is a secret, shown/copied only on user action, never logged. Native invitation is separate from legacy address-only links. Viewer reviews target/pin and explicitly connects using exact DER pin; TLS proves possession. Verify certificate validity/server purpose with the pinned certificate as the sole anchor; expected DNSname `knot-native`. No accept-all callback, TOFU reset or silent fallback.

Client sends hello over authenticatedTLS, containing EXACT JSON keys v=1, token (same32bytebase64url), name (1..64UTF8bytes, no Unicode control/format characters or line/paragraph separators), optionally the known scalar opt-ins `filesVersion=2` (the current file protocol in FILES.md) and `videoControlVersion=1` (Native.18). Each is independently optional; a legacy Hello remains valid. All other/duplicate keys and unknown versions fail. A new Mac requires a matched Native.18 host; an older host rejects its new Hello before claim. Show update guidance and never retry the possibly consumed token or relax authentication. Host rejects untrusted/public source IPv4, wrong/expired/reused token before any approval UI, capture or input. Constant-time comparison for equal-length decodedtoken. At most one pending invitation claim; atomic one-use claim before approval, userexplicitApprove within60seconds, reject/timeout consumes invitation. Sharing/capture begins only after valid run-specific authorization and media initialization. In legacy mode that authorization is explicit approval; in enrollment mode it is the later one-use T2 claim bound to the authenticated slot/run. File offers additionally require the displayed folder's local consent, matching enrollment grant scope (or legacy approval) and Hello opt-in. Stop, close or disconnect releases all injected keys/buttons, revokes files and destroys only owned resources. New screen connection requires a new invitation; no hidden saved trust or automatic reconnect. This temporary trust model is explicitly displayed by both apps.

Preclaim/enrollment deadlines use explicit completion-versus-expiry ownership. A queued timer callback cannot close a socket after successful completion wins. Completion checks the original monotonic budget independently of timer scheduling; backwards/late clocks fail closed and ordinary failure cleanup closes the connection.

Windows displays the exact current run's certificate pin for comparison with the reviewed Mac invitation. Approval displays the source IPv4 observed on the accepted socket and the viewer's claimed label; neither the label nor the address is an authenticated viewer identity. Invalid/preclaim connections cannot publish approval metadata. UI callbacks must belong to the displayed run.

Input revocation requests release of this session's owned input only. A failed `ReleaseAll` ends the connection before any later input is accepted, with up to three owned-release retry passes during teardown. Windows may refuse every attempt during a desktop transition; bounded cleanup is not proof of a successful OS release. Stop status reports the release request rather than claiming unverified success.

The viewer allows65seconds of read silence before Ready while waiting for approval or media initialization, with an overall125second stage deadline (60seconds approval, up to60seconds initialization and scheduling allowance). The host emits a heartbeat immediately before media initialization. After Ready the ordinary read/silence budget is10seconds and the first-presented-image budget is15seconds. These startup budgets bound viewer waiting; they do not make an in-process GPU/codec call preemptible. Native.18 permits a bounded30second preparation allowance for a pending negotiated video operation and retains the15second first-reset-image cap; ordinary heartbeat policy remains active. Applying a video change never reconnects the session.

## Binary frame envelope

Every message: u8kind + u32BEpayloadLength + exactly payloadLength bytes. Header5bytes. Unknown kinds, zero/oversize forbidden payloads, invalidUTF8/JSON, duplicate or extraJSON keys, out-of-order handshake and trailing data in typed packets fail closed. Never allocate from unchecked network lengths.

Client->host:
- 0x01 Hello: UTF8 JSON above, 1..4096bytes, first only; ten-second handshake/hello budget.
- 0x20 PhysicalKey: 4bytes = u8action(0up,1down), u16BEscanCode(1..255), u8extended(0/1). Max128retained pressed keys; no global hooks. ScanCodes are Windows set1.
- 0x21 Text: strict UTF8 1..1024bytes; committed text only, max512UTF16units; rejectNUL/invalidsurrogates. No arbitrary commands.
- 0x22 Pointer: 5bytes = u8action(0move,1leftdown,2leftup,3rightdown,4rightup,5middledown,6middleup), u16BEx,u16BEy. Coordinates normalized0..65535 over full captured rectangle; host maps to physical capturedmonitor then desktopvirtualscreen for SendInput.
- 0x23 Wheel: 8bytes = i32BEvertical,i32BEhorizontal, each -1200..1200.
- 0x24 ReleaseAll: empty, releases this session's accepted injected input only.
- 0x25 Heartbeat: empty, clientevery2s; ten-second inactivity timeout.
- 0x35 VideoControl (Native.18, negotiated only): exactly26bytes = u8version(1), u8operation(1 profile/2 pause/3 resume), u64BErequestID, u32BEmaxWidth,maxHeight,fps,bitrate. Pause/resume require all four configuration integers zero. IDs start1, strictly increase and never wrap; one operation outstanding. Full validation and field offsets are in [VIDEO-CONTROL.md](VIDEO-CONTROL.md).

Server->client:
- 0x02 Ready: strict JSON exactkeys v=1, codec="h264-annexb", width,height (even,16..3840/2160; at most8_294_400pixels), fps(1..60), bitrate(1_000_000..40_000_000), hardwareEncoder=true; optionally the complete four-field scalar file offer `filesVersion,filePort,fileToken,fileRootName` defined in FILES.md. Reject partial groups and unknown/duplicate keys. Native.18 may additionally offer `videoControlVersion=1` only after Hello opt-in, alongside `qualityVersion=1`, and only for a configurable, drainable source. Ready is one-use startup information; it never resets an established decoder. No ready before approved authenticated session + successful native media initialization.
- 0x03 Video: u64BEsequence(start1, strictlyincreasing), u64BEcaptureMonotonicMicroseconds(hostclock; NOT comparable to clientclock withoutsync), u8flags(bit0clean/IDR, otherbits0), then nonempty AnnexB H264 accessunit. Payload length18..4_194_304bytes excludes the5byte envelope; compressed data startsafter17payloadbytes and must independently pass AnnexB syntax validation. Every keyframe must provide parameter sets when available; decoder waits for validSPS/PPS+IDR. Reject malformed NAL structure/length; shared v1 limits are128NALs peraccessunit, atmost8SPS and8PPS, eachparameter NAL atmost65_536bytes. Enforce these onproducer/cacheprepend andbothconsumers, and validate decoded dimensions. No game/app launch, filesystem or shell messages.
- 0x04 Heartbeat: empty, hostevery2s evenifno desktop updates or video is paused.
- 0x36 VideoControlStatus (Native.18, negotiated only): exactly45bytes = u8version(1), u8operation, u64BErequestID, u64BEvideoEpoch, u8outcome, u8reason, u8videoState, u32BEactualWidth,actualHeight,actualFps,actualBitrate, u64BEnextSequence. Outcomes0 preparing/1 applied/2 rejected/3 rolledBack; state0 running/1 paused. Epoch starts0; a new encoder or rollback increments it once and announces the exact next global video sequence. Its retained first AU must be IDR with SPS/PPS. Preparing, rejected, pause and true no-op keep the epoch and announce nextSequence0. See [VIDEO-CONTROL.md](VIDEO-CONTROL.md) for reason codes, exact offsets and state validation.
- 0x7f Error: strict JSON exactkey code, authored enum `auth`,`expired`,`declined`,`busy`,`capture`,`encoder`,`input`,`protocol`,`timeout`,`closed`; max128bytes. No rawexceptions, endpoints, credentials or OS strings.

All clientposthello packet sizes asabove and max1024. Serverready4096/error128/video4MiB caps. The client paces all input envelopes, including heartbeats, to at most500/s. The host uses a monotonic token bucket refilling500envelopes/s with capacity1000, permitting a bounded TCP delivery burst while rejecting sustained abuse. Pendingclientinput remains <=256actions/16KiB. Only consecutive trailing mouse moves may be coalesced: wheel, key, text and button actions are ordering barriers. Adjacent wheel coalescing must preserve both axes, payload bounds and those barriers. A physically forwarded key-down owns its matching key-up independently of later text-mode/modifier changes. On saturation, revoke unsent work, ReleaseAll or disconnect, require focus recovery; no stale input replay. Stop/read/write/decoder failure and focusloss trigger release; host tracks only successfully injected input.

Decoder admission suspends the sole reader when its three-slot capacity is full; capacity includes decoded images waiting for MainActor delivery. Stop/cancellation wakes admission waiters. A documented non-error dropped-frame completion retires its slot without ending the session. A malformed compressed unit or genuine decoder error still fails closed; arbitrary compressed reference frames are never dropped to hide queue pressure.

Video uses backpressure: capture/encode the next frame after previouswrite, no unbounded raw/encoded frame queue. The host requests a256KiB socket send buffer; write completion is not peer delivery and OS/TLS buffering is separate from application queue bounds. Codec lowlatency and periodic IDR, bounded operation waits; hardware encoder required in normal host. Software encoding is permitted only in clearly named fresh synthetic CI tests, never an implicit runtime fallback. SDR only; unsupportedHDR/rotation/device state fails with fixedguidance.

## Native Windows media ABI

Owned C++ DLL `KnotNativeMedia.dll`, C cdecl exports, fixedwidth types/pack4; create/read/close called on one dedicated MTA thread. Config uint32 width,height,fps,bitrate. Info uint32 width,height,fps,bitrate; int32 left,top,desktopWidth,desktopHeight; uint32 hardwareEncoder. `void* kn_media_create(const KnMediaConfig*,KnMediaInfo*,int32_t*error)`. `int32_t kn_media_read(void*,uint8_t*buffer,uint32_tcapacity,uint32_t*written,uint32_t*flags,uint64_t*timestampMicros)`. `void kn_media_close(void*)`. status0=sample,1=tryagain;-1generic,-2unsupporteddisplay,-3nohardwareencoder,-4devicefailure,-5invalidargument. Normal read uses450ms poll slices and never writesbeyondcapacity. Native.18 additionally exports `int32_t kn_media_begin_drain(void*)` and `int32_t kn_media_read_drain(void*,uint8_t*buffer,uint32_tcapacity,uint32_t*written,uint32_t*flags,uint64_t*timestampMicros)` on that same owner MTA. Begin-drain succeeds with0; drain read returns0sample,1tryAgain,2drainComplete or a negative failure. Normal read never returns2. After begin-drain no capture or submission runs; reconcile sync NEED_MORE_INPUT or async METransformDrainComplete with in-flight output accounting. The managed transaction supplies a2second application drain deadline. No synchronous driver call is made preemptible by that deadline. Native media headers are authoritative for actual struct names; coordinate/ABI edits require notifying otherworker. Syntheticmedia tests use a separate test entry, not any remoteflag.

## Native.6 latency policy

The client explicitly disables Nagle aggregation for small input envelopes. Input is selected after its existing pacing wait so the latest consecutive move remains eligible; the500/s limit, action barriers, revocation epochs and sole writer are unchanged.

A single serial media reader actor owns framed reads, stream-order validation, Annex B parsing and one-time AVCC construction. It prepares at most one next unit while the existing MainActor decoder submission and three-ticket admission apply backpressure. It creates no per-frame tasks and does not drop compressed predictive frames. UI/input and stop/revocation can progress while media preparation runs; returned work is still checked against the current session identity.

The Windows media session owns one unnamed high-resolution waitable timer for its bounded poll waits. It replaces `Sleep(1)` without a global timer-resolution change or busy-spin. When there is no pending readback or encoder work, it waits until the pacer's next capture deadline; pending work and immediate retries retain the short interval. Requested waits are clamped to the remaining450ms read budget; existing2s progress/pending limits remain. A separate fresh QPC comparison records actual waits; policy simulation counts are not measured CPU use, production capture or input-to-display evidence. The normal hardware-only encode path still includes GPU readback and CPU NV12 copies. Full GPU-surface encoding and asynchronous retained-sample reuse require separate ownership/capability evidence.

CI additionally requires a twelve-frame3840×2160/60fps software-MFT-to-Mac decode fixture, alongside the existing30fps4K and120-frame fixtures. This proves codec/profile interoperability and resource bounds, not sustained hardware4K60 performance.

## 4K and local typing

Windows selects the starting quality before sharing: maximum3840×2160/30fps/40Mbps by default, optional4K60/40Mbps or1080p60/20Mbps. For legacy peers it remains the profile ceiling for that session. Negotiated Native.18 peers may subsequently request the bounded profiles below. Ready reports actual startup dimensions; capture preserves aspect and never upscales a smaller source. All producer/consumer size gates use even dimensions and the8,294,400pixel bound. Encoder in-flight count2, decoder slots3 and compressed access-unit limits remain unchanged. MFT output scratch uses a finite dimension-derived budget of two validated NV12 frames (at most24,883,200bytes at4K), distinct from actual compressed bytes. The allocation is only max(AUlimit, reported minimum), not the budget ceiling; larger reported minimums fail closed. This is a resource policy, not a guarantee for every encoder.

Mac ordinary typing uses its local input method and sends committed Unicode. Local Caps Lock language/capitalization events never become Windows Caps Lock toggles. Navigation/shortcuts remain physical with owned matching key-ups; composition is cancelled and late commits rejected on revocation/focus loss. Native fullscreen removes persistent chrome height while preserving one presenter and matching aspect-fit pointer geometry. Actual IME/fullscreen/GPU4K acceptance remains a device task.

Input0x26 carries a16-byte ordered Explorer handoff nonce; it is admitted only against session-owned left input and matched to the separately authenticated capture request. It is not a media-writer response or arbitrary file path. See TREES.md for expiry, cancellation and COPY-only semantics.

## Native.11 convenience extension

Ready may additionally contain the independently optional scalar keys `clipboardVersion=1`, `qualityVersion=1`, `trustedVersion=1`. Unknown keys, versions and incomplete file-offer groups remain rejected. A feature is enabled only when offered by the authenticated host.

Client `0x30` is an explicit clipboard request: operation byte (1 copy/2 paste),16-byte request nonce, then strict UTF-8 text (at most1,048,576 bytes, no NUL; copy text empty). Server `0x31` is operation/status byte pair, echoed nonce, then bounded strict UTF-8 (paste and unsuccessful replies have no text). One pending request is bound to the active session; late/cancelled replies cannot write the Mac pasteboard. The media transport retains ordinary4,096-byte outgoing limits, with only a fully validated clipboard-request exception. An explicit clipboard gesture queues release of held input before dropping local ownership, including validation failures.

Client `0x32` is one quality preference byte (0 automatic,1 text clarity,2 responsiveness); `0x33` is one pressure byte (0 healthy,1 overloaded). Server `0x34` is9 bytes: big-endian uint32 applied maximum FPS and bitrate followed by live-adjustment-supported0/1. For peers without Native.18 video-control negotiation, updates remain within the initial host-selected bounds and dimensions never change. With negotiated Native.18, this quality-v1 feedback remains within the current user-requested profile; a validated video reset barrier separately authorizes dimension changes. Status reports effective FPS/bitrate before any control status that references them. One media MTA owns the dynamic encoder operation. Unsupported changes retain prior settings and report that limitation.

Registered-device provisioning and fresh challenge/grant exchange run on independent pinned TLS TCP48635, active only while Windows sharing is enabled. Persistent credentials are not reusable invitations and do not bypass the existing source-bound one-use media claim. See the Native.11 Daily use section in [README.md](README.md) and source-backed tests. [UPDATES.md](UPDATES.md) governs the separate signed publishing/installation contract.


## Native.18 live video control and idle suspension

Both updated apps are required; an unnegotiated connection receives no video-control offer. The authoritative wire, transaction, UI and validation rules are [VIDEO-CONTROL.md](VIDEO-CONTROL.md). A requested profile uses preset bounds1920×1080,2560×1440 or3840×2160, FPS30/60 and target bitrate1,000,000..40,000,000. Preserve source aspect ratio, never upscale the physical source and never change Windows display modes. The initial Windows selection is the starting profile rather than the negotiated session's ceiling. Unsupported/out-of-policy valid requests receive bounded rejection without disturbing current video; malformed packets or state are fatal. Admission uses one bounded mailbox and a2second reconfiguration cooldown.

The sole MTA media writer suspends and releases session-owned input, cancels pending clipboard shortcuts and Explorer handoff, then sends preparing before a potentially slow operation. Drain and synchronously write every old AU, close the old source, open the requested hardware source serially, validate the unchanged physical capture rectangle and prime a bounded first IDR. Send its reset barrier followed by that retained AU; the global video sequence never resets. A target initialization failure reopens/primes the prior configuration and reports rolledBack with a new epoch. Failed rollback or changed source/topology remains terminal. Two output-duplication sources must never coexist.

Pause drains/closes only video capture and encoding; authenticated media heartbeats, registration/recovery ownership, optional audio and file services remain active. Physical input, clipboard shortcuts and Explorer input are suspended atomically, including late callbacks. A closed InputSession never reopens. Retain the default-input-desktop metadata security check while paused so lock/secure desktop still ends unsupported sharing. Resume primes a fresh IDR and announces a running reset barrier; failure may leave the same authenticated session paused.

Mac holds the last image, drains old decoder admission with a bounded5second wait, checks callbacks against session identity plus video epoch and resets video-pressure history after a barrier. The connected toolbar's **화질** control separates draft settings from actual host-confirmed settings and exposes applying, rollback, unsupported and paused states. Idle settings offer off/1/5/10/15/30/60minutes, default10minutes with background-only enabled. Only this app's focus and accepted interaction timestamps drive the existing ticker. Returning to or using the app resumes an automatic idle pause; a manual pause requires explicit resume. Swallow the resume gesture, preserve ordinary sleep/disconnect cancellation and never inspect global activity or other apps. Fixtures use inert policies, fresh synthetic sources and isolated nonsecret preferences; actual hardware transitions, power savings and long-idle behavior require separate device acceptance.
