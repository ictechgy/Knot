# Native.18 live video control

This extension changes only video on the existing authenticated media TLS connection. It never issues another invitation, changes a pin, re-pairs, changes the Windows display mode, or reopens audio/file services. Initial Windows quality becomes the starting profile. Windows sharing explains that the connected Mac may request up to4K60/40Mbps. Preserve aspect ratio and never upscale the physical source.

## Negotiation and bounds

New Mac media Hello opts in with optional scalar `videoControlVersion:1` alongside existing fields. The new Windows parser accepts legacy Hello unchanged and omits the new offer for it. Only an opted-in, configurable/drainable source adds `videoControlVersion:1` to Ready; qualityVersion1 must also be present. Ready remains one-use startup information, never a reset packet. Both new apps are required for the new feature. An old host rejects the new Hello before claim; show update guidance, never retry a possibly consumed token or silently relax authentication.

Runtime bounds:1920x1080,2560x1440,3840x2160 preset bounds; FPS30 or60; target bitrate1,000,000..40,000,000. Actual dimensions obey existing even/minimum/pixel limits and may be smaller. One request outstanding, no wrap, bounded2s reconfiguration cooldown. A malformed wire/state is protocol-fatal; a structurally valid unsupported/out-of-policy request receives a rejected result without disturbing current video. Preserve existing quality-v1 policy and feedback within the current user-requested profile.

## Wire (network byte order)

Client kind0x35:26 bytes. Offsets: version:u8=1 at0; operation:u8 at1; requestID:u64 at2; maxWidth:u32 at10; maxHeight:u32 at14; fps:u32 at18; bitrate:u32 at22. Operations1=profile,2=pause,3=resume. Pause/resume require all configuration integers zero. IDs strictly increase from1 and never wrap. Overlapping requests are rejected/bounded without an unbounded response queue; the supported client serializes them.

Host kind0x36:45 bytes. Offsets: version:u8=1 at0; operation:u8 at1; requestID:u64 at2; videoEpoch:u64 at10; outcome:u8 at18; reason:u8 at19; videoState:u8 at20; actualWidth:u32 at21; actualHeight:u32 at25; actualFps:u32 at29; actualBitrate:u32 at33; nextSequence:u64 at37. Outcomes0=preparing,1=applied,2=rejected,3=rolledBack. Reasons0=none,1=unsupported,2=outOfPolicy,3=busy,4=initializationFailed. State0=running,1=paused. Report actual configuration, not measured throughput.

Epoch starts0. A new encoder (successful profile/resume or rollback) increments epoch exactly once and announces nextSequence=current global video sequence+1. Its first AU MUST be that exact sequence, actual IDR with SPS+PPS. Global sequence never resets. Preparing/rejected/pause/true no-op have unchanged epoch and nextSequence0. Applied/rolledBack running with unchanged epoch is allowed only for an unchanged profile/no-op. Paused has no subsequent video AU until a running reset barrier. Heartbeats and other bounded sidecar/control replies may continue.

## MTA transaction and rollback

Only the existing MTA media writer writes status and video or changes media. Validate/admit first; suspend and release owned physical input; cancel pending clipboard shortcut/Explorer handoff. Send preparing before a potentially slow video operation. Drain old encoder without any new capture/submission; synchronously write every old AU. Use a2s application drain deadline and existing450ms poll slices. Never open two output-duplication sources at once. Dispose old source, create requested hardware-only source serially, validate unchanged physical capture rectangle, and prime one bounded first IDR before writing the reset barrier and retained AU. On target failure reopen and prime the old configuration, emit rolledBack with a new epoch. If rollback also fails use existing terminal media policy. Synchronous driver calls cannot be preempted; do not claim a hard hardware timeout.

C ABI: add `kn_media_begin_drain(void*)` and `kn_media_read_drain(void*,buffer,capacity,written,flags,timestamp)` on the same MTA. Drain read returns existing sample0/tryAgain1, drainComplete2, or negative failure. Normal read never returns2. Track async METransformDrainComplete and sync NEED_MORE_INPUT completion; reconcile in-flight accounting. No capture pumping after beginDrain. Preserve hardware-only production path; software fixtures remain separate.

Pause drains old video, releases/closes only media capture/encoder and emits applied paused with unchanged epoch. Keep authenticated heartbeat/input-control reader, registration/recovery ownership, audio and file channels. No physical input, clipboard shortcut or Explorer input capture may run while paused/preparing; use an InputSession gate to suspend/release atomically, without reopening a closed input session. Resume creates/primes saved profile and sends a fresh running reset barrier. A profile request while paused is rejected busy; resume before applying settings. A failed resume can remain paused with an authored rejected result; no PIN is requested. Preserve the default-input-desktop security check while paused (injected inert policy in fixtures); lock/secure desktop still terminates unsupported sharing rather than permitting unattended access. Source/topology changes are terminal as before.

## Mac transaction and idle settings

Keep SessionModel phase.streaming, TLS/session identity, the existing InputSession, files and audio intact. The ordinary input-revocation revision may advance to fence released keys/queued input; the video epoch is independent of that revision and session identity. Route control through the one bounded existing writer. Do not forward physical input while paused/preparing; a resume gesture is swallowed rather than replayed remotely. Drain old decoder admission with a bounded5s wait before invalidation; retain the last displayed image. Guard decoder callbacks by both session identity and video epoch. Apply new dimensions/decoder only from a validated reset barrier and require its announced first IDR. Reset video-pressure history. Pending operations receive a bounded30s network preparation allowance; the first reset image has a15s cap. Normal heartbeat policy remains unchanged; paused is not disconnection.

Settings: video idle timeout defaults10minutes, background-only defaults true; offer0/off,1,5,10,15,30,60minutes and an explicit background-only toggle. Viewing a video without interaction must not unexpectedly stop under the default. Track only this app's focus and accepted interaction timestamps; never inspect other apps, OS activity history or global input. Reuse the current session ticker. Idle pause is video/input-only; audio/files/heartbeats remain active. App activation or user use resumes an automatically paused stream. A manual pause requires explicit resume. Serialize resume desired during a pending pause; cancellation/disconnect/sleep cannot revive a stale control. Persist only these nonsecret settings through production NativePreferences; fixtures never use real defaults or notifications.

UI: direct **화질** control in the connected toolbar, keyboard-accessible popover with preset bounds/FPS/target Mbps, Apply, actual host-confirmed settings, applying/unsupported/rollback/paused states. Separate draft selection from applied values. Reveal fullscreen controls normally; never reconnect merely to apply quality. Expose idle settings in connection settings and this popover. Retain Quiet Sidebar/system styling.

## Validation scope

Use fixed cross-language vectors, malformed/version/state gates, old/new Hello behavior, bounded mailbox, no capture during drain/pause, all old AUs before barrier, first IDR, serial close/open/rollback, input release/no late injection, host lock policy, stale decoder and timeout/cancel/idle fake-clock tests. Actual hardware1080p/1440p/4K transitions, power savings, driver initialization latency and long-idle device behavior remain separate acceptance.
