# Automatic file setup

File enrollment removes the normal JSON-file round trip. It does not combine screen PIN pairing and SSH authorization. The supported first-run direction is Mac client to Windows file host; reverse and Linux file enrollment are not implemented.

The Mac explicitly creates or reuses its dedicated selected SSH identity, suggests its local addresses, and starts a temporary TLS listener on one chosen private LAN/Tailscale IPv4 address. It accepts connections only from the currently selected Windows IPv4 address. A separate `knot-enroll://` link contains the selected address, ephemeral port, request UUID, exact SHA-256 certificate pin, and a random 256-bit capability. It is a secret invitation, never a discovery/address-only invitation, a saved setting, or a log field. The TLS private key and certificate are generated in process memory using Security.framework; no keychain item, temporary private-key file, or persistent trust exception is created.

Choose matching routes on both computers: use their Wi-Fi/LAN addresses on the same LAN, or their Tailscale addresses for a Tailscale connection. If the Mac selects the Windows Tailscale address but the enrollment reaches the Mac over LAN (or the reverse), the Windows source address differs from the admitted peer and setup is refused. Select matching addresses and create a new link; the app never broadens peer admission or silently substitutes the trusted Windows address.

Windows connects outbound using TLS 1.2 and checks the exact certificate bytes against the link's pin in this connection's callback. It does not weaken global TLS validation, fetch a URL, follow redirects, use a proxy, or open a Windows enrollment listener. After capability authentication, the Mac closes admission to new connections. Four-byte big-endian length frames carry at most 16 KiB of public JSON. The canonical existing Mac request and Windows reply contracts are reused.

Windows validates the request ID, its selected Mac address, public key and allowed addresses. The user checks these and explicitly approves the normal native UAC broker. The original non-elevated desktop SID, protected native payload, dedicated transfer account, restricted SFTP configuration and narrow client-address firewall contract remain unchanged. No SSH private key or account password crosses the channel. The public Windows reply must match the original request ID, client key and selected Windows address. Receipt is acknowledged only as receipt, not as trust. The Mac still asks the user to compare the SSH fingerprint shown on the Windows screen before persisting it. A changed SSH key is never silently adopted.

The Mac allows the first capability authentication for two minutes and bounds each unauthenticated TCP/TLS connection to eight seconds. The first valid authentication closes new admission and starts a fixed ten-minute provisioning/reply window, so installing OpenSSH and approving UAC need not finish in the short admission window. Windows likewise extends its initial two-minute connection deadline once, only after validating the complete Mac request. Replayed authentication, repeated validation, or activity cannot renew either deadline. A monotonic one-use gate rejects duplicate replies, expired sessions, canceled sessions and wrong peers; expiry cannot reopen a session. Completion, cancel and app shutdown close the transport. The UI rejects changes to the selected PC/key/addresses before applying the reply; active setup also blocks new screen/file operations and update installation. Failed or canceled exchange does not delete or rotate the saved screen certificate, selected SSH identity, or saved host pin.

Local Windows provisioning and network enrollment are separate transactions. Once the user has approved UAC, canceling/expiring the enrollment cannot undo a Windows administrator operation already started. Its late reply is rejected on the Mac. The wizard describes this state and retains the public-result JSON recovery path. The user can start a new automatic exchange using the same existing key or export the existing result; uninstalling first would revoke file access and is unnecessary.

A client cannot safely create its Windows file permission at installer time before its Mac public key and allowed addresses are known. The installer includes the automatic workflow; first use requires one explicit cross-device setup approval and SSH fingerprint comparison. Existing manually configured OpenSSH deployments retain their existing refusal/manual-integration policy.

The ephemeral Mac listener can be blocked by client isolation or a Mac firewall policy. Use a reachable Tailscale address or the JSON recovery path; the app does not disable firewall policy. The link currently transfers by paste or displayed QR. It is not a globally registered operating-system URL handler and Windows does not capture a camera/image to scan it in this version.

Synthetic tests compile the actual Swift protocol, native TLS identity/server, and C# parser/pin/framing code. They exercise memory-only generated certificates, monotonic expiry/cancel/replay state, malformed/oversized/fragmented frames and wrong pins using synthetic bytes and memory streams. They do not open sockets, read existing identities, invoke UAC, enable OpenSSH or inspect application UI. Actual Windows UAC, Mac firewall and a real cross-device TLS exchange remain device integration checks.
