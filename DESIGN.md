# Design

## Native.18 connected video controls and idle optimization (2026-11-08)

The user requests changing stream resolution, FPS and quality without ending an established connection, and configurable idle optimization. This supersedes the native convenience extension's fixed-dimensions restriction for negotiated native.18 peers only. Follow [native-engine/VIDEO-CONTROL.md](native-engine/VIDEO-CONTROL.md). Keep the Quiet Sidebar, semantic native controls and existing fullscreen behavior. Put **화질** directly in connected controls, with draft settings, one Apply action, actual host-confirmed values and explicit applying/rollback/unsupported states. Hold the last image during a video-only transition; preserve the current authenticated connection, registration, audio and files.

Idle video suspension defaults to10minutes while this app is in the background, with off/1/5/10/15/30/60minute choices and a background-only setting. Resume automatically on return only for an automatic idle pause; manual pause needs explicit resume. Never replay the gesture that resumes into Windows. No capture/encoding or remote physical input runs while paused, but authenticated keepalive, files and optional audio continue. System sleep and manual termination retain native.17's existing lifecycle. Current registered transport recovery uses capped continuing retries; the earlier six-attempt/budget wording below is historical and superseded by native.17.

A fresh authenticated eight-digit connection must reuse a unique saved exact-certificate credential regardless of the remember checkbox. Separate the unchanged saved authorization record from this session's authenticated LAN/Tailscale endpoint; persist neither an address migration nor a new credential implicitly. Reconnect still requires fresh proof with the same key and pin. Ambiguous saved identities or unavailable credential storage cannot invent recovery authority. Fixed bounded diagnostics distinguish disabled recovery, missing/ambiguous/unavailable saved authority, sleeping/suspended intent and retry lifecycle without including endpoints, names, pins, IDs or keys. Their elapsed seconds are since app launch, not connection duration. These source fixes do not establish the cause of an individual long-sleep incident.

## Native.14 registered-session sleep recovery (2026-11-07)

Observe Mac sleep/wake through an app-owned power adapter. Keep an explicit in-memory recovery intent for the current registered target, separate from UI selection. Sleep synchronously revokes the old connection, input and child sessions and pauses retries. Wake waits briefly for network readiness, resets the bounded retry budget and uses a fresh trusted challenge with the unchanged host pin. Duplicate wake and stale callbacks must not create parallel connections.

Sleeping suspended recovery is itself a visible pending state, even before a wake-delay task exists. Connection, review and target-selection entry points must reject new work before mutating that intent while the system is sleeping. Manual cancellation and forgetting remain effective; a failed credential removal keeps the credential listed with an error but never silently restores the connection the owner asked to revoke.

Never connect an idle saved PC merely because it is registered. Manual disconnect/window close, forgetting a device, disabling automatic reconnect, selecting a new target and terminal trust/protocol failures revoke recovery intent. A transiently interrupted registered session may resume after sleep even if its earlier retries were exhausted. New Windows host runs keep the existing off-by-default playback consent. Tests inject a fresh notification center, fake clients/channels and clock gates; never sleep the machine or access real stores, devices or system notifications.

## Native.14 audio review follow-up (2026-11-07)

Keep the current Windows owner-consent boundary. Same-share audio retry may reuse only the existing exact host pin/address and derived key; stop is terminal, and a new automatic Windows host still clears audio consent. Display connecting separately from unavailable, expose audio-only retry in the same speaker control, and release remote input before either action.

Short valid PCM bursts must begin after the 960-frame threshold or a bounded20ms priming deadline. Keep one timer, queue-generation and timer-identity guards, the4,800-frame cap, and stop/flush cancellation. Coalesce mute delivery into one worker so slow callbacks cannot override the latest UI choice. Windows may reset consecutive authentication failures after a successful authenticated connection; eight consecutive failures still retire only audio and produce an authored notice. Never relax authentication or revive an old grant.

The fail-closed H.264 ambiguity policy remains: do not guess a packing interpretation or drop compressed predictive frames to avoid an encoder error. Real-driver compatibility, physical audio and AV synchronization remain separate acceptance boundaries.

## Native.13 playback audio and repaint/pressure contract (2026-11-07)

This supersedes the native preview's earlier audio exclusion only for Windows playback → Mac. Keep the existing connection flow and add **Windows 재생 소리 포함 · 마이크 제외** before Windows sharing, off on every app launch/update. Consent belongs to the current manually started share; an old resume grant cannot enable it. Never capture a microphone. Both apps must be updated. The connected Mac speaker control offers local mute/unmute, with authored unavailable status; an audio failure never stops video.

Audio uses fixed stereo48kHz PCM16 (about1.536Mbps before overhead), independent same-certificate pinned TLS TCP48636, the current media-authorized peer and a domain-separated HMAC session key. Media-v1 Hello/Ready remain unchanged. No per-app volume/source controls, DRM compatibility, precise audiovisual synchronization or measured performance is promised. Tests use only fresh synthetic data and fake capture/output, never existing screen/audio, devices, preferences or user stores. See [native-engine/AUDIO.md](native-engine/AUDIO.md).

Windows rounded buttons repaint their entire client rectangle with the nearest solid parent background before drawing the rounded surface. Transparent layout wrappers must not leave stale/dark corners; preserve clipped repaint, focus, disabled, hover and selected states across supported DPI sizes. Mac quality feedback observes repeated pressure in a bounded recent window, with minimum event thresholds and hysteresis for stable adaptation. Preserve compressed-frame order and bounded decode admission; do not drop frames to implement this feedback. Native.13 also fixes H.264 sample-framing detection while retaining the wire contract. Synthetic checks do not identify a particular GPU's stutter cause or prove real4K performance improvement.

## Native certificate compatibility correction (2026-11-07)

Native.11's five-year persistent TLS leaf is rejected by the Mac SSL policy. Its Framework default RSA factory also does not guarantee an actual2048-bit key when assigned through the inherited KeySize setter. Native.12 must explicitly construct and verify a2048-bit RSA key and issue a365-day total lifetime, including backdating, then test the same production PFX-generation/import path across Windows and Mac. Public-key strength must be checked again after PFX import and in the Windows-produced DER on Mac.

Never disable SSL policy or adopt a replacement pin automatically. An existing overlong or weak-RSA stored identity requires an explicit Windows primary action, **호환 인증서로 전환하고 공유**. Explain before that action that the old identity is replaced and registered Macs need a new eight-digit pairing. Conversion happens only while idle after the direct button click; automatic restart/resume cannot authorize conversion. Corrupt/expired/keyless state fails closed. New installations need no migration action.

Mac errors distinguish an exact-pin mismatch, OS certificate-policy rejection and network failure; provide authored recovery guidance without showing tokens, raw OS logs or private keys. Fresh synthetic UI fixtures render both migration and certificate-error states without opening a user store or adapter.

The explicit conversion action is idempotent under the same lease: after validating an already-compatible identity, return successfully without replacing its bytes or revoking credentials. This lets a stale second form proceed after another process completed conversion. Missing or invalid identities still fail, and genuine revoke/publication errors remain visible.

## Native convenience extension (2026-11-06)

The user authorized remembered devices, reconnection, explicit text copy/paste, Mac shortcut compatibility, quick activation, file convenience, adaptive quality and automatic updates. This supersedes the native slice's earlier prohibition on persistent trust and its clipboard/reconnect/update exclusions only as implemented and validated below. Keep the Quiet Sidebar and the primary PC-list/connect flow; place secondary actions inside connected controls or a single settings disclosure.

- Device registration requires explicit consent after authenticated short-code enrollment. Store credentials in Keychain/CurrentUser DPAPI; revoke explicitly. Fresh reconnect authentication must bind the pinned host identity and source/session; never adopt replacement certificates silently. Manual disconnect/stop cancels reconnect.
- Read/write clipboard text only for an explicit copy/paste gesture in an authenticated session. No ambient clipboard polling. Mac shortcut compatibility is optional; preserve OS Mission Control and input-method ownership.
- Remember nonsecret preferences separately from credentials. Global quick activation uses one registered shortcut, never a keyboard event tap. A synthetic renderer must not register shortcuts, read preferences or access user data.
- File retry copies only unfinished upload items; completion gives an inline announcement and explicit Finder reveal. No automatic opening of received content. Byte-offset resume is not implied.
- Quality adapts bounded bitrate/frame pacing; display dimensions/topology stay fixed. Surface unsupported live encoder adjustment honestly.
- Automatic installation requires a configured trusted signed publisher feed. Verify platform/build/size/hash/signature before install, preserve per-user state and relaunch. An unconfigured publisher shows unavailable instead of downloading unsigned updates.

## Implementation constraints

- System OpenSSH SFTP transport, no shell string interpolation.

Knot's signed application updater is separate from Moonlight and never replaces its pairing profile.
